# 中国专利说明书附图的图型选择与样式

本文件从 `drawio-skill` 的图型库中筛选适合专利说明书的表达方式。目标不是把通用架构图、BPMN 或 UML 原样搬进申请文件，而是用最少的图形语法清楚表达可主张的技术关系。

## 图型路由

| 专利披露重点 | `diagram_type` | Draw.io 基础图型 | 推荐方向 | 适用边界 |
|---|---|---|---|---|
| 系统、装置、模块及接口关系 | `system_block` | Architecture / 简化 C4 component / SysML internal block | 横向优先 | 使用普通矩形、存储形状和虚线容器；不显示 C4 stereotype、部署环境装饰或品牌图标 |
| 方法步骤、算法分支、异常处理 | `method_flowchart` | Enhanced Flowchart / UML Activity | 纵向优先 | 椭圆表示起止、矩形表示处理、菱形表示判断；决定分支必须标“是/否”或具体条件 |
| 多主体通信、端云交互、时序先后 | `interaction_sequence` | UML Sequence / Cross-functional flowchart | 横向优先 | 主体少且时间先后重要时使用；可用泳道或生命线，但不引入与发明无关的 UML 装饰 |
| 状态及其转换条件 | `state_machine` | UML State Machine | 横向或纵向 | 状态必须来自说明书；转换条件使用 Draw.io 原生线条文字 |
| 数据产生、处理、存储和输出 | `data_flow` | Data-flow / Architecture | 横向优先 | 数据对象和处理模块必须区分；不使用缺乏解释的抽象云图标 |
| 物理结构、组件嵌套、端口关系 | `internal_structure` | SysML internal block / simple block diagram | 按结构决定 | 适用于装置、终端或模块内部结构；端口和连接器必须有说明书依据 |
| 不同角色/设备分工和跨域交接 | `cross_functional_flow` | Swimlane | 横向时间轴 | 仅当“谁执行什么”是技术方案的一部分时使用；不要把一般业务职责画成专利发明点 |
| 网络节点、链路和通信区域 | `network_topology` | Network topology | 分层 | 仅当网络布置或通信路径属于技术特征；默认使用通用节点，不使用厂商品牌图标 |
| 数据结构、记录字段和索引关系 | `data_structure` | ERD / UML class 的简化形式 | 横向 | 仅当数据结构本身参与解决技术问题；不用 crow's-foot 或类方法区等无必要符号 |

## 通常不采用的通用图型

- **Mind map**：不表达确定的技术关系。
- **装饰性云架构图和品牌图标**：容易使申请文件产品化、宣传化。
- **完整 BPMN**：事件、消息、网关语法过重；除非流程引擎本身就是发明对象，否则改用简化流程图或泳道图。
- **完整 UML class**：若保护重点不是对象模型，改用系统框图或数据结构图。
- **C4 System Context**：外部系统和人物图标通常过于产品架构化；需要时收敛为简洁系统框图。
- **手绘、暗色、3D、阴影、渐变、图标化主题**：不适合正式专利申请文件。

## 布局原则

1. 每幅图只承担一个表达目的；系统组成和复杂方法流程通常拆图。
2. 系统框图优先横向，方法流程优先纵向，时序/泳道优先横向。
3. 先划分层、列或泳道，再放置节点；相邻层之间保留至少一个清晰路由走廊。
4. 上下相邻节点中心对齐，保持单一竖直边；左右相邻节点中心对齐，保持单一水平边。
5. 复杂线路沿外围走廊绕行，不穿过无关节点、标签或容器标题。
6. 关系标签使用 Draw.io 原生线条文字，由 Draw.io 管理文字与线条的相对位置；不得另建独立文本框模拟标签。
7. 只对确需固定路线的边设置 waypoint；直线关系不添加 waypoint。
8. 节点标签宜为一至三行；过长说明放入说明书，而不是塞入图面。

## 专利图面视觉基线

以下参数是从 `drawio-skill` 的网格、间距、连接点和图型预设中收敛出的专利版默认值。节点可以因文字长度调整尺寸，但不得通过无限放大方框或缩小字号规避排版；最终验证会按 A4 基准画布归一化检查每行汉字数、外框/文字块高度比例、文本容量和纵向有效空白。用户修改稿的包围盒压缩率和节点宽高分布可作为紧凑布局目标，但应保持字号并从原始拓扑安全重建，不能整体缩放或复制参考图边。

| 项目 | 默认值或范围 | 使用规则 |
|---|---|---|
| 网格 | 10 px | 节点坐标、宽高和主要 waypoint 对齐到网格 |
| 主节点 | 宽 160—240 px，高 60—90 px | 同一语义层级尽量同宽同高 |
| 节点间净距 | 横向不少于 80 px，纵向不少于 70 px | 多连接区域另留约 80 px 路由走廊 |
| 字体 | 中文优先无衬线字体；全图统一 | 主标签 14—16 px，旁注/分支标签 12—14 px；避免小于 12 px |
| 节点边框 | 1.2—1.5 px | 重点节点不靠加粗到 2 px 以上制造层级 |
| 连接线 | 1.2—1.5 px，深灰或黑色 | 默认正交、单一箭头、无发光和动画 |
| 原生线条文字 | 由 Draw.io 自动布局，可使用白色标签背景增强可读性 | 保持在线条附近，不遮挡节点边界；必要时只调整 edge label 的原生位置参数 |
| 页边留白 | 四周至少 40 px | 图形视觉重心居中，避免贴边和大面积单侧空白 |


### 节点与文字联动

- 所有技术节点必须显式设置 `fontSize`，并使用 `whiteSpace=wrap`；任一可见行最多12个汉字，超出时必须显式换行，禁止依赖默认字号、自动缩小字体或仅靠自动折行。
- 节点外框高度不得超过实际文字块高度的2倍；直接上下相连节点扣除原生关系标签和一个箭头头部后的有效空白必须处于相邻节点较小字体行高的2倍至3倍之间。
- 以竖向 A4 的 827×1169 Draw.io 坐标为归一化基准；横向图交换宽高。扩大画布时，节点尺寸和字号必须同比例增加。
- 归一化字号不得小于 14；节点宽度/字号比例不得大于 18，节点高度/字号比例不得大于 9。
- 按中英文显示宽度、左右各8px留白、上下各4px留白和1.2倍行高估算换行；预计超过4行或所需高度超过节点高度时必须扩大节点、调整文字或拆图。
- 不得单独缩小某个节点的字号来容纳长文字；同层同类节点应优先保持统一字号，尺寸随内容在合理范围内调整。
- 最终 PNG 仍须目视确认，因为字体替换、菱形有效文本区和 Draw.io 实际换行不能仅靠 XML 估算完全证明。

### 形状语法

- 同一技术角色使用同一种形状和样式；不要为了“好看”混用圆角、胶囊、六边形和图标。
- 系统/模块通常使用矩形或轻微圆角矩形；存储可使用圆柱；判断仅使用菱形；起止仅在方法流程中使用椭圆或圆角终止框。
- 容器只表达技术边界、部署边界或主体边界，采用无填充或极浅中性色、细实线/虚线；不得用大面积色块压过内部技术节点。
- 连接线默认 `orthogonalEdgeStyle` 且 `rounded=0`；分支较多时给同一节点的入口/出口均匀分配锚点，避免多条线重叠在同一短线段上。
- 只有技术含义明确的双向关系才使用双箭头；普通调用、数据传输和控制流均使用单向箭头。

### 视觉层级

1. 第一层是发明主体或主流程，使用主色/黑白实线和稳定尺寸。
2. 第二层是支撑模块、存储或次级步骤，使用次色或中性灰，但不降低文字对比度。
3. 第三层是外部对象、条件文字和注释，使用白底、虚线或较轻边框。
4. 不使用第四种视觉层级；需要更多层级时应拆图，而不是继续增加颜色、线型或形状。

## 克制彩色策略

中国发明专利附图可以使用彩色，但颜色只用于降低复杂图的阅读负担，不能成为唯一的技术语义载体。

### 默认建议

- 简单结构图、机械图、单线流程图：`patent_monochrome`。
- 软件系统图、多主体时序图、复杂流程图：可选 `patent_restrained_color`。
- 同一申请的全部附图使用同一套配色和线宽。

### `patent_restrained_color`

以 `drawio-skill` 的 corporate / colorblind-safe 风格为参考，但降低饱和度和装饰性：

| 角色 | 填充 | 边框 | 典型用途 |
|---|---|---|---|
| primary | `#EAF2F8` | `#405F73` | 主处理模块、终端、服务 |
| secondary | `#EEF4EA` | `#52634E` | 存储、已确认状态、辅助模块 |
| decision | `#F8F2E6` | `#706347` | 判断、门控 |
| neutral | `#F4F4F4` | `#4A4A4A` | 外部系统、一般对象 |
| external | `#FFFFFF` | `#666666`，虚线 | 发明边界外的对象 |

硬约束：

- 每幅图最多三种非白填充色；
- 白色背景、深色文字和深色边框；
- 禁止渐变、阴影、透明叠加、暗色背景、霓虹色和装饰性配色；
- 红/绿不得作为唯一的成功/失败区别；颜色语义必须由形状、文字或线型重复表达；
- 转为灰度后，节点边界、文字和技术关系仍必须清楚；
- 颜色不代表权利要求范围、必要性或法律评价。
