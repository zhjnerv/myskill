# choice-oracle 决策

## 2026-10-30 用决策模型而非生成式视觉模型

**背景**：最初按"让多模态模型写评语再解析分数"设计，用户明确要的是决策模型评分。

**决定**：接 Cloudflare `clef-flash` 的 System One API，输入类型化 `questions`，只要概率。

**放弃**：自由文本 prompt + JSON 解析。理由是决策模型直接给每档概率，比让生成模型自报分数更稳定，
也不会出现"讲的是一套、分数是另一套"。

**影响**：分数归一化、加权、门槛制裁必须由脚本算；模型只负责概率。评分卡成为主要可调面。

**回退**：保留 `image-analysis-fallback` 做图片描述类任务，两者职责不重叠。

## 2026-10-30 逐图评分与择优分成两条路径

**背景**：一次请求只产出一份答案，多图请求里的 `score` 题无法拆成逐图分数。

**决定**：默认逐图一请求；`--compare` 时多图合并、只问 `mode=compare` 的 choice 题。

**放弃**：一次请求给多图各打分。实测语义上不成立，会串分。

**影响**：N 张图逐图评分要 N 次调用；择优只要 1 次。

## 2026-10-30 密钥只放仓库外

**背景**：本仓库是公开仓库。

**决定**：实机配置写 `~/.clef/config.json`；仓库内只留 `config.example.json`，
`skills/**/config.local.json` 进 `.gitignore`。

**影响**：skill 部署到别处时要单独配置，这是有意的。
## 2026-10-30 改名为 choice-oracle

**背景**：skill 从"给图片打分"扩展为"按问题给图片或多段文字打分择优"，`image-score` 名不副实。

**决定**：改名 `choice-oracle`（选择之神）。候选名由本 skill 自评，用户要求加强中二权重后它 7.90 分第一；
曾考虑 `magi`（EVA 的决策系统），因版权风险放弃。

**影响**：目录、frontmatter、registry 条目同步改名；未部署过，无旧 junction 需清理。
